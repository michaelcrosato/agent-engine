# 0003: zod schemas as the single source of truth

**Status:** accepted

## Context

Components and data files need defaults, validation with good errors, TypeScript types, editor
autocomplete, documentation, inspector widgets, and tool argument schemas. Writing each by hand
drifts.

## Decision

Declare every component (`defineComponent` with `field.*` helpers), content kind
(`defineContentKind`), and tool argument set (`defineTool`) once with zod 4. Field helpers
attach metadata (doc, unit, widget, content `ref`). Everything else is derived:

- validation with JSON paths and file positions (`engine/schema/validate.ts`),
- defaults and runtime conversion (`[x, y, z]` → `Vector3`, degrees → `Quaternion`),
- TypeScript types (`ComponentData<typeof Health>`),
- JSON Schemas for editors (`schemas/`, regenerated by `npm run check`),
- reference docs (`docs/reference/`), the editor inspector, CLI flags and MCP tool schemas,
- reference checks between files (`ref` metadata).

## Consequences

- Adding a field in one place updates validation, docs, editor, and tools.
- Schemas stay `.strict()`: unknown keys are errors with a list of allowed keys.
- zod is a runtime dependency of the engine (it validates data in the browser too).
